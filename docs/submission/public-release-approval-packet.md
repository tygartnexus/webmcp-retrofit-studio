## Publication actions requiring exact approval

No action in this section is approved merely because the local project is ready.

1. Create a public repository named `webmcp-retrofit-studio` under the exact owner-approved account.
2. Add the exact owner-approved open-source license and copyright identity.
3. Push the reviewed revision and enable public read access.
4. Deploy that same revision to the exact owner-approved no-cost hosting target.
5. Record or render the final demonstration from the verified live revision.
6. Upload the approved rendered file, title, description, thumbnail, channel, audience setting, and Public visibility to YouTube.
7. Populate the Devpost form with the independently read-back live, repository, and video URLs plus the approved description and testing instructions.
8. Perform the final Devpost Submit action before the official deadline.

Each action must be followed by a fresh provider or signed-out public readback. A successful CLI response, editor state, upload progress bar, or deployment operation is not by itself proof of public availability.

## Exact pre-approval evidence bundle

Before requesting publication approval, present one compact release receipt containing:

- the repository account, repository name, public visibility, default branch, revision identifier, and proposed license text;
- the hosting provider, account/project identifier, intended public URL, build command, output directory, cost tier, and security-header configuration;
- the final video file path, SHA-256 digest, exact duration, audio-stream check, title, description, thumbnail path, target channel, audience setting, and Public visibility;
- the exact Devpost title, tagline, description, testing instructions, live URL, repository URL, video URL, image list, entrant type, and team member list;
- fresh test results, dependency audit, secret scan, asset-provenance review, browser UAT, and live WebMCP UAT;
- confirmation that the three public artifacts all correspond to the same reviewed revision.

Approval should bind to that exact receipt. Any change to the revision, license, public accounts, URLs, rendered video, submission copy, assets, or entrant identity requires a refreshed receipt and renewed approval.

## Recommended approval sequence

1. Resolve entrant, ownership, license, design-reference, narration, channel, and hosting decisions.
2. Approve and publish the repository; read it back signed out.
3. Separately approve and manually dispatch the Pages deployment workflow; read the result back independently. Ordinary pushes run CI but do not deploy.
4. Run the live WebMCP protocol and preserve the passing evidence.
5. Produce the final video from that live revision.
6. Approve and publish the exact video; read it back signed out.
7. Assemble the final Devpost payload and compare every claim with the public artifacts.
8. Obtain exact final-submit approval, submit, and read back the resulting entry.
